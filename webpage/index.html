AI scientist for practical quantum error correction

OmniQEC: discovering practical quantum error-correcting codes by an AI scientist

OmniQEC turns QEC design into an iterative discovery process. An LLM-based orchestrator couples rapid code-level exploration with physically grounded circuit synthesis and decoder evaluation, allowing promising qLDPC codes to be judged by how they actually perform on a processor.

Why OmniQEC

Beyond code-centric discovery

A quantum code that looks strong algebraically can still perform poorly after hardware constraints, syndrome extraction, circuit noise, and decoding are taken into account. OmniQEC closes this gap by making implementation-level evidence part of the search itself.

01

Conventional search

Optimize a proxy

Candidates are ranked using algebraic quantities such as [[n,k,d]] and the figure of merit kd²/n. These are fast to compute, but they do not capture the complete implementation.

02

OmniQEC

Optimize what the processor experiences

Promising candidates are compiled into syndrome-extraction circuits, sampled under circuit-level noise, and ranked by decoder-estimated logical error rate.

03

The consequence

Evidence reshapes the search

Circuit-level results return to the orchestrator, so later generations can move away from proxy-optimal but operationally weak regions of the design space.

Core idea

Practical QEC discovery is a code-circuit-decoder co-design problem, not a code-parameter ranking problem.

Design specification

Start from practical constraints

The user describes the desired code family, total qubit budget, weight limit, connectivity, and optimization objective.

  • Complete physical-qubit budget, not data qubits alone
  • Hardware and syndrome-extraction constraints
  • Target code family and circuit-level objective

Main result

A circuit-level performance frontier

Across four qLDPC construction families and three LLM backends, the best discovered codes show steadily stronger logical-error suppression as the complete physical-qubit budget increases.

N = 98

First BB crossover

All three backends discover implementations that surpass the [[72,12,6]] BB reference, with the first improvement appearing at 98 total physical qubits.

N = 240

Stronger large-budget frontier

The strongest Claude and GPT campaigns exceed the larger [[144,12,12]] BB reference within the explored budget.

kd²/n ≠ LER

The proxy can mis-rank codes

Several codes with lower algebraic proxy scores deliver better circuit-level logical error rates, motivating direct physical evaluation.

Validation and ablation

The advantage persists beyond a single search point

Physical-error sweeps and loop ablations test whether the discovered advantage is robust and whether both feedback paths are necessary.

29.23× lower LER at p = 0.002 for the strongest candidate
Γ = 5.60 representative fitted suppression exponent versus 3.79 for BB
Both loops are required for reliable, practically relevant discovery

Practical cost

Scaling code size does not dominate LLM usage

Token consumption changes only weakly with the physical-qubit budget. Larger candidates primarily increase slow-loop circuit-evaluation time, while LLM-side cost is governed more by backend behavior and pricing.
